# RAGFailBench

Code, data and results for **"RAGFailBench: Automated Construction and Controllable
Failure-Injection Benchmarking for Retrieval-Augmented Generation"** (IEEE BigData 2026).

- Camera-ready paper: [`paper/IEEE BigData2026 - RAGFailBench.pdf`](paper/IEEE%20BigData2026%20-%20RAGFailBench.pdf)
  (LaTeX source alongside; build with `tectonic "paper/IEEE BigData2026 - RAGFailBench.tex"`)
- Every number in the paper comes from files in this repository, and every table can be
  regenerated from the saved run data **without any LLM calls** (see
  [Reproduce the paper's numbers](#reproduce-the-papers-numbers)).

```
corpus snapshot → QA generation → rule + judge + baseline validation → failure injection → evaluation → regression gate
                                              └── sampled human audit (QA of seeds and failure cases)
```

### Main results (three seeded runs, 561 parent seeds)

- Construction: QA acceptance 74.8% ± 1.0%; failure verification 94.9% ± 0.3%.
- Human audit (single primary annotator, automatic verdicts hidden): HAR 84.0% [71.5, 91.7]
  on 50 seeds; failure-case validity 96.3% [87.5, 99.0] on 54 cases.
- `conflict` is the largest paired drop for every model (26.6–30.4 points) under every
  conflict scoring rule we tried. `context_noise` and `evidence_position` cause no drop with
  eight passages; `chunk_boundary` costs gpt-oss 5.4 points.
- The model ranking on FRS depends on the conflict scoring rule (Table VI), so the paper does
  not rank models by FRS.
- Regression gate: a three-month Wikipedia update passes (21/21 cells); a simulated
  retrieval-depth change (eight passages truncated to four) leaves clean accuracy unchanged
  and is blocked in 12/21 cells.

### Scope and limitations (as stated in the paper)

- No retriever is run: the reader receives fixed contexts. Retrieval metrics (Recall@k, MRR,
  nDCG) are out of scope; the top-k experiment truncates contexts rather than re-retrieving.
- English, single-hop Wikipedia only; no enterprise connector is evaluated.
- Regeneration is run by re-running the pipeline on a new snapshot; nothing triggers it
  automatically.
- The human audit is one primary annotator on a sample; inter-annotator reliability was not
  established. A second person labeled the same rows after seeing the primary labels, so that
  pass is not reported; its sheets are kept in `reviews/audit_v2/` as a record.
- The multi-part question rule was applied **after** the runs as a filter
  (`ragfailbench filter-seeds`), removing 11/16/12 of 200 seeds per run with all derived
  cases; removed rows are kept in `data/runs/<run>/6_final/excluded_multi_part/`.
- Conflict is scored by a lenient *handled* rate (gold, both values, or an acknowledged
  conflict), which is not answer accuracy; stricter rules are in Table VI.

## Reproduce the paper's numbers

From the saved run data, no API access needed:

```bash
make setup
.venv/bin/python scripts/paper_tables.py     # tables.md/.tex, Fig. 2
.venv/bin/python scripts/paper_stats.py      # tables_ci.md/.tex: CIs, McNemar, signals, sensitivity
.venv/bin/python scripts/audit_stats.py      # reviews/audit_v2/audit_stats.json
.venv/bin/python scripts/audit_tables.py     # tables_audit.md/.tex
make stability-report validation-contribution
.venv/bin/python -m ragfailbench regression-gate --baseline-run pilot_stability_s42 \
    --candidate-run regress_b_s42 --unpaired --name snapshotA_vs_B
.venv/bin/python -m ragfailbench regression-gate --baseline-run regress_b_s42 \
    --candidate-run regress_b_s42_topk4 --paired --name topk8_vs_topk4
.venv/bin/python -m pytest -q
```

The outputs should be identical to the committed files (`git diff` stays empty apart from
figure timestamps).

Re-running generation and evaluation needs model access (Amazon Bedrock models through an
OpenAI-compatible gateway; see [`models.md`](models.md) and `.env.example`). One seeded run:

```bash
C=configs/stability/pilot_stability_s42.yaml
python -m ragfailbench generate-qa -c $C --no-resume
python -m ragfailbench validate -c $C
python -m ragfailbench select-seeds -c $C
python -m ragfailbench generate-alternates -c $C
python -m ragfailbench inject-failures -c $C --judge
python -m ragfailbench filter-seeds -c $C          # post-hoc multi-part filter, as in the paper
python -m ragfailbench evaluate -c $C --replace-all
python -m ragfailbench report -c $C
```

LLM outputs at temperature > 0 (QA generation, 0.2) are not bit-reproducible; the committed
run data is what the paper reports.

## Data

| Path | Contents |
|---|---|
| `data/runs/pilot_stability_s{42,123,2026}/` | The three seeded runs: candidates, validation results, clean seeds, failure cases, evaluation results |
| `data/runs/regress_b_s42/`, `regress_b_s42_topk4/` | Snapshot B rebuild and the top-k = 4 run |
| `data/runs/<run>/6_final/evaluation_results.jsonl` | One row per model × item (prediction, EM, F1, judge verdict, abstention, conflict outcome) |
| `data/runs/<run>/6_final/failures/*.jsonl` | Failure cases by operator, with verification metadata |
| `data/runs/<run>/6_final/llm_raw*.jsonl` | Raw LLM call logs (gateway URL replaced by `<EVAL_BASE_URL>`) |
| `reviews/audit_v2/` | Human-audit sample, labeling guide, labeled sheets, `manifest.json` (hidden automatic verdicts) |
| `reviews/judge_review_v1/` | Judge-validation sheet and agreement report |
| `reports/regression/` | Corpus diff, seed staleness, gate reports |

Corpus: 768 English Wikipedia pages (12,366 chunks), fetched through the MediaWiki API on
2026-08-01 (snapshot A) and 2026-10-28 (snapshot B), with page revision ids recorded.

## Failure operators

Every clean and failure case shows the reader exactly eight passages; unused slots hold
off-topic padding checked not to contain the answer.

| Operator | Expected | Severity (low / medium / high) |
|---|---|---|
| `missing_evidence` | abstain | other pages only / up to 2 neighbouring passages of the source page / gold chunk with the answer sentence deleted |
| `hard_negative` | abstain | 2 / 4 / 8 topically similar passages without the answer |
| `conflict` | answer or flag | gold + a copy differing only in the answer: copy in slot 2 / copy in slot 1, gold in slot 2 / copy in slots 1 and 7, gold in slot 8 |
| `context_noise` | answer | gold + 7 others, of which 2 / 4 / 6 topically similar |
| `chunk_boundary` | answer | supporting sentence split into 2 adjacent pieces / 2 pieces with a distractor between / 3 pieces with distractors between |
| `evidence_position` | answer | gold passage in slot 1 / middle / slot 8 |

Abstain-expected cases are checked for any surface form of the answer and audited by an LLM
judge independent of the generator.

## Code layout

```
src/ragfailbench/
├── sources/       # MediaWiki ingest, snapshot re-fetch
├── processing/    # filter, clean, dedup, chunk
├── generation/    # QA generation, conflict alternates
├── validation/    # rules, judge, baseline, seed selection, post-hoc seed filter
├── failures/      # failure operators + verification
├── evaluation/    # metrics, runner, conflict outcomes
├── reporting/     # reports, human-review and judge-review export
└── experiments/   # multi-seed stability, regression gate
scripts/           # paper tables, statistics, audit sampling and statistics
paper/             # camera-ready LaTeX and PDF
```

Configuration: [`configs/stability/`](configs/stability/) (paper runs) and
[`configs/regression/`](configs/regression/) (snapshot B and top-k = 4). Key settings:
8-passage context budget, difficulty quota 40/40/20, generation temperature 0.2, evaluation
temperature 0, evaluation concurrency 9 (gateway limit 10).
